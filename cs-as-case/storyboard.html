공통 기준

  • 상태 — 접수 → 처리중 → 처리완료 → 종료, 분기 추가 확인 필요 · 반려. 담당자 배정·이관은 상태가 아니라 이벤트로 기록한다.
  • 처리완료와 종료 분리 — 처리완료 = 담당자가 조치를 마친 시점, 종료 = 접수자가 고객 안내까지 마친 시점.
  • 시간 기준 — 시작 = 문의 수신 일시(등록 시 입력, 기본값 현재 시각), 끝 = 종료 시각. 전화 연동(CTI)은 Phase 2에서 문의 수신 일시를 자동으로 채운다.
  • 반려와 이관 — 반려 = 접수 정보 부족으로 접수자에게 돌려보냄. 담당자를 잘못 배정한 경우는 이관(사유 오배정)으로 처리한다.
  • Activity Log — 모든 상태 변경·담당자 이벤트·정보 수정을 시간순으로 추가 기록한다(추가 기록만 허용).

  1. 1약국(필수) — 약국명·사업자번호·전화번호로 검색해 선택. 선택하면 약국명·사업자번호·대표 전화가 표시된다. 이 약국 정보로 CASE-03의 약국 이력이 묶인다.
  2. 2문의 수신 일시(필수) — 기본값은 현재 시각이고, 상담원이 실제 전화 받은 시각으로 고친다. 목록 `접수 ~ 종료`의 시작 시각. 시스템 등록 시각은 별도로 저장한다. Phase 2(CTI)에서는 통화 시작 시각이 자동으로 들어간다.
  3. 3문의 카테고리(필수) — 대분류 › 중분류 › 소분류. 약국 이력의 `같은 카테고리` 탭과 재발 확인의 기준. 카테고리 체계 확정 필요
  4. 4제품/서비스(필수) — 예: Client 3.0, 키오스크, 약사님용 앱. 선택지 목록 확정 필요
  5. 5증상(필수) — 약국이 말한 현상을 그대로 적는다.
  6. 6발생 환경(선택) — OS · VAN사 · 카드단말 모델. 처리 단계에서 보완할 수 있다.
  7. 7담당자(선택) — 선택하면 등록과 동시에 배정되고 담당자에게 알림이 간다. 비워두면 미배정으로 등록되고, 접수자가 CASE-03에서 배정한다.
  8. 8내부 메모(선택) — 내부 공유용. 향후 외부 챗봇 데이터 범위에서 빠지는 영역이다.

  1. 1헤더 — 약국명 · 증상 요약 · 상태 배지 · 접수 ~ 종료 시간(CASE-01과 같은 표기). 종료되면 `10:02 ~ 12:01 (1시간 59분)`으로 고정된다.
  2. 2상태 버튼 — 현재 상태와 보는 사람(접수자/담당자)에 맞는 버튼만 보인다. 처리중 담당자 기준: `추가 확인 필요` · `이관`(CASE-04-2) · `반려`(CASE-04-3) · `처리완료`. 전체 조합은 CASE-05.
  3. 3기본정보 — 등록 정보(CASE-02). 종료 전까지 `수정` 가능하고, 수정하면 Activity Log에 `정보 수정`으로 기록된다.
  4. 4담당자 — 접수자 · 최초 담당자 · 현재 담당자 · 종료 처리자를 나눠 보여준다. 현재 담당자 옆에 이관 횟수 표시. 미배정이면 이 영역에 `담당자 배정` 버튼(CASE-04-1)이 나온다.
  5. 5처리정보 — 담당자가 처리하면서 입력한다. 조치 내용·처리 결과는 처리완료 시 필수. 원인 필수 여부 확정 필요
    재발 여부: `재발`을 고르면 `이전 Case 연결`로 같은 약국의 지난 Case를 골라 연결한다(재발률 집계 근거).
  6. 6내부 메모 — 작성자 이름과 함께 누적된다.
  7. 7Activity Log — Case 생성 · 담당자 배정/이관 · 상태 변경 · 반려 · 정보 수정을 시간순으로 기록. 이관·반려는 사유까지 남긴다. 기록은 추가만 된다.
  8. 8이 약국의 다른 Case — 같은 약국으로 등록된 다른 Case(최근 5건).
    · 같은 카테고리(기본 탭): 지금 Case와 카테고리가 같은 건만 → 재발 여부 확인

    탭에 건수 표시. 행 클릭 → 그 Case 상세. `전체 보기` → CASE-01에 이 약국 필터를 건 상태로 이동.

취소반려
    CASE-04 · 컴포넌트
  1. 104-1 담당자 배정 — 미배정 Case에 담당자 1명을 정한다. 접수자가 연다. 배정하면 `담당자 배정` 이벤트가 기록되고 담당자에게 알림. 최초 담당자는 이때 정해진다.
    반려 후 재접수할 때도 이 Modal이 열리며, 기본 선택값은 반려한 담당자다.
  2. 204-2 이관 — 현재 담당자가 다른 담당자에게 넘긴다. 새 담당자·사유 필수. 사유 유형 `오배정`(처음부터 잘못 배정) / `담당 변경`(처리 중 다른 담당이 필요) + 상세 사유. 기존·신규 담당자·사유·일시·수행자를 기록하고 새 담당자에게 알림. 상태는 그대로 유지된다. 사유 유형 목록 확정 필요
  3. 304-3 반려 — 접수 정보가 부족할 때 담당자가 접수자에게 돌려보낸다. 반려 사유 필수. 상태가 반려로 바뀌고 접수자에게 알림. 접수자는 기본정보를 보완한 뒤 `보완 후 재접수`로 다시 접수한다.
